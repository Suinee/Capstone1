# 공공서비스 망설임 감지와 단계별 도움

기준: `public-backend` (`a11db6c4e541fe279b4314569546fe41395f229e`). 브랜치: `public-hesitation`.

## 범위

주민등록·가족관계·납세증명 신청 화면과 전입신고 4개 단계에 기존 점수 엔진을 연결한다.
감지 점수에 따른 **1·2·3단계 도움 UI**를 제공한다. 3단계는 미리 작성한 상세 조작 안내이며 AI 호출을 하지 않는다. 도움 동작과 검증 방법은 `public-help.md`를 참고한다.
기존 키오스크의 도움 UI와 이벤트 채널은 공공서비스 Provider에서 실행하지 않는다.

- 클릭, hover, 마우스 탐색, 스크롤, 입력 중단/삭제 후 재입력, 선택 변경 수집
- 주민등록 신청의 필수 항목 오류, 전입신고 이전주소 조회의 필수 선택 오류 기록
- 비활성화된 다음 버튼은 검증 실패로 기록하지 않음
- 실제 입력 문자열, 전화번호, 상세주소, 이름, 선택값 원문은 감지 로그에 넣지 않음
- 선택지는 정해진 코드/인덱스로 구별하여 서로 다른 옵션 클릭을 같은 버튼의 반복 클릭으로 합치지 않음
- 한 번 공공서비스에 진입한 동안 라우트/전입 단계 간 동일 감지 세션 유지
- 화면 재방문은 새 screenVisitId로 화면 행동 점수 초기화, 왕복 점수는 같은 서비스 과제에서 유지
- 홈·서비스 설명·신청내역·완료 화면, 탭 숨김, 서버 저장 대기 중에는 측정 중단
- 저장 실패 시 입력 화면에서 측정 재개, 성공 시 완료 처리 및 로그 즉시 전송
- 늦은 응답은 다른 화면 방문의 측정 상태에 영향을 주지 않음
- 가족관계는 완료 후 `새 신청 시작` 버튼으로 새로운 방문/측정 시작

## 초기 설정

| 화면 | 시간 지연 기준 |
| --- | --- |
| 주민등록 신청 | 60초 |
| 가족관계 신청 | 60초 |
| 납세증명 신청 | 45초 |
| 전입신고 유의사항 | 90초 |
| 전입신고 기본정보·이전주소·현재주소 | 각각 60초 |

`src/features/publicHesitation/publicHesitationConfig.js`에서 조정한다.
기존 키오스크와 동일하게 **시간 초과만으로 가산하지 않고 보조 행동 근거가 필요**하다.
약한 신호 1점, 강한 신호 2점, 동일 5초 묶음의 최대 점수만 가산하고 중복 근거를 재사용하지 않는다.
자동 도움 기준은 3·6·9점이다. 사용자는 수동으로 도움을 열고 상세 안내로 확장할 수 있으므로 감지 수준과 실제 표시 수준은 다를 수 있다.
`ruleVersion=public-help-1.1`은 사전실험 전의 초기 기준이며 정확도가 검증된 임계값이 아니다.

## 로그와 기존 신청 DB의 연결

기존 `/api/hesitation/logs` 저장 API와 SQLite `hesitation_log` 테이블을 재사용한다.
새 테이블이나 DB 마이그레이션은 필요 없다. 기본 주기는 5초이며 공공서비스 이탈·페이지 종료·신청 완료 시에도 전송을 시도한다.
기존 전송 큐가 실패한 로그를 보관하고 재전송한다.

- 감지 sessionId는 Provider 진입마다 새로 생성된다. 새로고침하면 새 감지 세션이다.
- `screen_enter.task.context.applicationSessionId`는 기존 모의 신청 API의 익명 sessionId다.
  이를 이용하면 새로고침 전후 감지 세션을 신청내역과 연관 지을 수 있다.
- 저장 성공 시 `behavior.event.type=submission_succeeded`에 `requestId`를 기록한다.
  기존 신청 테이블의 같은 requestId로 연결한다.
- `submission_started`, `submission_failed`, `submission_succeeded`는 서버 요청 수명주기 기록이다.
  클릭/입력 횟수 분석에 포함하지 않는다. 숨겨진 탭에서도 응답 결과를 보존하되 점수 계산에는 넣지 않는다.
- `help` 로그에는 실제 안내 상태, 표시 단계, 관찰/강조 대상, 안내 종류, 자동/수동/닫기 사유를 남긴다. `status=visible`인 항목이 표시 기록이다. 숨김/초기화 기록을 도움 제공 횟수로 합산하지 않는다.

`npm run dev`에서 우측 하단 개발 패널로 화면 ID, 세션 ID, 측정 상태, 점수, 최근 신호를 확인한다.
공공서비스 개발 패널은 기본적으로 접혀 있다. 펼쳐서 세부 지표를 확인할 수 있다. 패널과 콘솔 로그 버튼 자체는 수집에서 제외한다. 제품 빌드에서는 개발 패널이 표시되지 않는다.
저장 확인: `GET /api/hesitation/sessions/{개발패널의 sessionId}/logs?limit=1000`.
많은 기록은 응답의 `hasMore`/`nextAfterSequence`로 다음 페이지를 조회한다.

## 실행 및 확인

백엔드 실행은 `backend/docs/public-service-api.md`를 따른다(Java 21).
프론트는 `frontend`에서 `npm install`, `npm run dev`로 실행한다.
API 주소를 바꾸려면 `VITE_API_BASE_URL`을 설정한다.

```sh
npm run test:public-hesitation
npm run test:public-help
npm run test:public-service
npm run build
```

`test:public-hesitation`은 외부 의존성 없이 Node 내장 테스트로 감지 규칙, 중복 처리,
단계 왕복, 대기/숨김 처리, 완료/실패, 늦은 응답, 새 신청을 검증한다.
`npm run test:hesitation`으로 점수 엔진 감사·공공서비스 감지·도움 테스트를 함께 실행할 수 있다.

### 시연 체크

1. 주민등록 신청에서 주소 없이 신청하기를 두 번 눌러 오류 반복 신호와 점수를 확인한다.
2. 시도·시군구를 선택하고 신청하면 DB 저장 후 내역 화면에서 측정이 중단되는지 확인한다.
3. 전입신고 기본정보에서 전화번호 입력 → 2초 이상 멈춤 → 삭제/재입력을 두 번 반복한다.
4. 전입신고 이전주소/기본정보를 빠르게 두 번 왕복하여 이전 단계 반복 신호를 확인한다.
5. 전입신고 완료 화면에서 점수가 더 증가하지 않는지 확인한다.
6. 가족관계 신청 완료 후 새 신청 시작을 누르면 새 방문으로 측정이 재개되는지 확인한다.
7. 백엔드 연결을 끊고 신청하면 오류 표시 후 다시 측정하며, 복구 후 재시도할 수 있는지 확인한다.

도움 대상 결정·강조·단계별 안내는 연결됐다. 남은 연구 작업은 사용자 실험을 통한 감지 기준과 안내 효과 검증, A/B 실험 모드 연결이다.

## 구현 검증 결과

- 감지/상태 전환 Node 테스트 10개와 도움 대상/단계 테스트 10개 통과
- 기존 공공서비스 API 통신 테스트 2개 통과
- Vite 제품 빌드 및 변경된 코드 ESLint 검사 통과
- Chromium에서 네 서비스 신청 전 과정을 조작해 실제 Spring Boot/SQLite 신청·로그 저장 및 조회 확인
- 브라우저에서 주민등록 반복 오류, 전입신고 입력 수정, 가족관계 새 신청, 통신 실패 후 측정 재개 확인
- 공공서비스 → 키오스크 전환 시 감지 Provider 분리 및 브라우저 실행 오류 없음 확인

브라우저 검증은 별도 임시 SQLite DB를 사용했으며 저장소의 mydb.sqlite는 변경하지 않았다.
