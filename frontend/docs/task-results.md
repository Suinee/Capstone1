# 과제별 결과 기록과 RESULT

## 확인 순서

1. 백엔드와 프론트엔드를 실행한다. 새 집계 API가 있으므로 이미 실행 중인 백엔드는 재시작한다.
2. 홈 → 실험 설정에서 서비스·모드·기록 용도를 선택한다. 기본값은 `연습·개발 확인`이다.
3. 키오스크 메뉴 조작 또는 공공서비스 신청 화면에 진입해 과제를 수행한다.
4. 완료 후 메인페이지 RESULT에서 해당 과제와 기록 용도를 선택한다.
5. 다른 모드로 새로 시작해 같은 과제를 수행하고 비교한다. `집계 CSV 저장`은 선택한 기록 용도의 전체 과제 집계를 내보낸다.

RESULT의 기본 용도는 `사용자 실험`이다. 연습 결과는 기록 필터를 바꾸어 확인한다.
표와 평균 완료시간 막대그래프 아래에 수행별 완료시간·오류 횟수 꺾은선 그래프를 표시한다.
기본 모드는 파란 실선, 적응형 모드는 붉은 점선이다. 각 모드의 최근 완료 기록 최대 30건을
오래된 완료 순서대로 표시하며 한 건은 점으로 표시한다. 같은 가로축 번호는 같은 참가자나
동일 시각을 뜻하지 않는다. `그래프 수치 보기`에서 개별 수치를 확인한다.
5초마다 미전송 로그를 재전송하고 결과를 갱신한다. 네트워크가 끊기면 오류와 다시 불러오기 버튼을 표시한다.
로그가 서버에 반영되기 전에는 집계가 늦게 표시될 수 있다.

## 수행의 범위

별도 과제 시작 버튼 없이 **측정 가능한 첫 화면 진입**을 시작으로 삼는다.
실험 설명·서비스 상세·신청내역 화면에서는 시작하지 않는다.

- 키오스크: 메뉴 화면의 로딩 완료부터 주문 전체. 장바구니 추가·옵션 완료는 과제 완료가 아니다. 모의 결제 완료에서 마감한다.
- 주민등록·가족관계·납세증명: 신청 화면 진입부터 서버 저장 성공까지.
- 전입신고: 유의사항 단계부터 마지막 신청 저장 성공까지. 단계 왕복도 같은 수행이다.
- 공공서비스 목록/상세로 나가거나 서비스를 바꾸면 기존 수행을 중단 처리한다.
- 서비스 화면을 벗어나거나 새로고침·탭 종료 시 중단을 기록한다. 완료된 기록은 이후 이탈해도 중단으로 바뀌지 않는다.
- 브라우저 강제 종료 등으로 종료 로그가 도착하지 않은 기록은 `진행·종료미확인`으로 남는다. 임의로 완료 또는 중단으로 추정하지 않는다.

실험 ID 아래의 각 수행에는 별도 `attemptId`가 있다. 새로고침은 기존 수행을 중단하고 새 수행으로 시작한다.
참가자 ID와 정해진 주문/신청 과제 지시문, 무작위 조건 배정은 아직 포함하지 않는다.

## 지표 정의

- `durationMs`: 기존 엔진의 활성 측정 시간 차이. 숨겨진 탭, 로딩, 서버 저장 대기, 모의 결제 처리, 완료·확인서 표시 시간을 제외한다. 실제 벽시계상의 총 소요시간과 다르다.
- `clicks`: 서비스의 수집 대상 클릭 수. 도움 UI·개발 패널 클릭 제외. 수량 변경 등 정상 조작 클릭은 포함한다.
- `errors`: 입력 검증 오류를 `attemptId` 기준으로 한 번씩 집계한다. 같은 시도의 여러 항목 오류는 중복 집계하지 않는다. 통신 실패는 입력 오류에 포함하지 않는다.
- `automaticHelpCount` / `manualHelpCount`: 도움창이 숨겨진 상태에서 표시되는 한 회를 자동/수동으로 구분한다. 열린 안내의 갱신·단계 확장은 추가 횟수로 세지 않는다.
- `maxHelpLevel`: 실제 표시한 최고 도움 단계.
- 시간·횟수 평균은 완료한 수행만 포함한다. 완료율은 완료 건수 / 전체 시작 건수다. 진행 중·종료미확인 건수도 전체 시작에 포함하며 따로 표시한다.

서로 다른 과제를 섞어 평균을 내지 않는다. 과거 고정 수치와 그래프는 제거했다.
참가자 수·인과적인 개선 효과를 의미하지 않으며, 실제 실험에서는 동일한 과제 지시와 수행 조건을 맞춰야 한다.

## 저장·조회

기존 로그 전송의 재시도·중복 방지를 활용한다. 별도 이중 쓰기 대신 `hesitation_log`에
`type=behavior`, `event.type=task_attempt_snapshot`으로 수행별 결과 스냅샷을 저장한다.
시작, 활성 시간 약 5초마다, 완료·중단에 기록하며 `experiment`에 조건과 `dataset`을 함께 보존한다.
서버는 `(session_id, attemptId)`별 가장 높은 로그 순번의 결과만 집계한다.
도착 순서가 뒤바뀌거나 동일 로그를 다시 보내도 한 수행으로 처리한다. 기존 로그는 결과로 재해석하지 않는다.

`GET /api/results/summary?dataset=study` (`practice`도 지원)

과제·모드별 `started`, `completed`, `interrupted`, `inProgress`, 평균 `durationMs`, `clicks`,
`errors`, `automaticHelpCount`, `manualHelpCount`를 반환한다. 완료 건이 없으면 평균은 null이다.
사용자 로그인 없이 사용하는 로컬 실험용 API 범위는 기존 API와 동일하다.

`GET /api/results/trends?dataset=study&taskCode=kiosk-order`

선택한 과제의 모드별 최근 완료 수행을 최대 30건씩 반환한다. `attemptId`, `mode`,
`durationMs`, `errors`, `endedAt`을 포함한다. 최신 로그 순번으로 수행 상태를 확정한 후
완료된 수행만 선택하므로 재전송으로 점이 중복되지 않는다. 두 그래프의 세로축은 각각 초·회다.

검증: `node --test tests/*.test.mjs`, `npm run build`, 백엔드 `HesitationLogApiTests` 및 `PublicApplicationApiTests`.
