# 공공서비스 단계별 도움 UI

`public-hesitation` 브랜치의 감지 기능에 네 공공서비스용 도움 UI를 연결했다.
실제 기관에 제출하거나 입력을 대신 결정하지 않고, 현재 화면의 조작 방법을 안내한다.

## 표시 방식

| 단계 | 자동 기준 | 표시 |
| --- | --- | --- |
| 1 | 3점 이상 | 해당 입력/선택/버튼 강조 + 한 문장 안내 |
| 2 | 6점 이상 | 강조 + 항목의 의미와 진행 방법 설명 |
| 3 | 9점 이상 | 강조 + 설명 + 순서대로 따라 할 3개 조작 단계 |

3단계는 고정된 화면별 상세 안내다. AI API, AI 생성, 직원 호출은 포함하지 않는다.
자동 기준은 기존의 약한 신호 1점·강한 신호 2점·5초 묶음 최대 점수 정책을 그대로 사용한다.
입력값이 아닌 DOM의 완료 여부만 즉석에서 확인하고 다음에 할 조작을 찾는다.

- 주민등록: 시도 → 시군구 → 선택발급의 필수 체크 → 신청 순으로 누락 항목 안내
- 가족관계: 대상자·증명서 종류·일반/상세/특정·공개 범위·수령·사유별 안내
- 납세증명: 공개 범위·목적·수령·신청 안내
- 전입신고: 유의사항 → 연락처/사유 → 주소조회/이사 가는 사람/동의 → 현재주소/세대구성 안내
- 이전주소 조회의 현재 체험 데이터는 **경상북도 구미시**임을 안내
- 특정 입력/선택에서 신호가 발생하면 그 항목을 우선 안내하고,
  다음/신청 버튼에서 막힌 경우에는 미완료 선행 항목으로 안내
- 시간 지연 등 과제 전체의 신호와 수동 도움은 현재 완료 상태에 따라 안내

## 상호작용

- 신청 화면의 `화면 도움 받기` 버튼으로 수동 요청 가능
- `설명 더 보기` → `순서대로 보기`로 현재 도움 대상을 유지한 채 단계 확장
- 같은 대상을 상세 안내 중일 때 낮은 자동 신호 때문에 단계가 다시 축소되지 않음
- `항목 위치 보기`를 눌렀을 때만 해당 위치로 스크롤하고 입력 요소에 초점 이동
- 자동 표시 시 스크롤이나 초점을 빼앗지 않음
- 닫기/ESC 후 30초 동안 자동 재표시 억제. 수동 요청은 즉시 가능
- 선택 변경·텍스트 입력 재개 시 현재 도움 해제. 이후 새 신호는 다시 평가
- 단계/화면 변경, 저장 대기, 탭 숨김, 신청 완료 때 도움과 강조 해제
- 조건부 항목의 제거/비활성화 시 강조 정리
- 도움 패널과 버튼은 행동 수집에서 제외
- 작은 화면에서는 안내창 내부 스크롤과 하단 여유 공간으로 원래 항목에 접근 가능

안내창은 모달이 아니므로 원래 화면을 계속 조작할 수 있다.
라디오·체크박스는 라벨을 함께 강조한다. 그룹에는 그룹 외곽선과 내부 입력 요소의
`aria-describedby`를 적용한다. 닫으면 기존 설명 연결을 보존하며 안내 연결만 제거한다.

## 로그 해석

기존 `help` 로그 API와 SQLite를 그대로 사용한다.

- `status`: visible / hidden / suppressed
- `level`: 실제 도움 표시 수준. 감지 점수 수준과 다를 수 있음
- `observedTargetId`: 감지된 원래 항목
- `highlightTargetId`: 실제 강조할 항목
- `helpKey`: 화면 안내 문구 식별자
- `reason`: newSignal / manualRequest / manualExpansion / userClosed / actionCompleted / screenChanged
- `sourceSignalKey`, `sourceAddedScore`: 자동 안내를 발생시킨 근거

`status=visible`은 표시 또는 갱신 기록이다. 갱신·수동 단계 확장까지 모두 별개의
도움 세션으로 세지 않도록 분석 시 화면 방문/대상/상태 전환을 함께 사용한다.
입력한 주소·전화번호·사유 문자열은 도움 내용이나 로그에 넣지 않는다.
`ruleVersion`은 `public-help-1.0`이다.

## 코드와 확인 방법

- `publicHelpContent.js`: 화면별 짧은 안내·설명·상세 조작 순서
- `resolvePublicHelp.js`: 다음 필수 항목 판단과 감지 대상 → 안내 매핑
- `PublicHelpUI.jsx`, `PublicHelpUI.css`: 안내창, 수동 확장, 닫기, 위치 보기
- `usePublicHelpHighlight.js`: 입력/선택/그룹 강조 및 접근성 설명 연결
- `HesitationProvider.jsx`: 도움 컴포넌트/대상 결정 함수 주입. 기본값은 기존 키오스크
- `adaptiveHelpState.js`: 단계·닫기 억제·수동 확장·화면 변경 상태 처리

```sh
npm run test:public-help
npm run test:public-hesitation
npm run test:public-service
npm run build
```

자동 도움 시연: 주민등록 신청에서 주소를 비운 채 신청하기를 두 번 누른다.
5초 이상 지난 뒤 같은 동작을 반복하면 점수가 누적되어 단계가 올라간다.
상세 확인은 개발 패널을 펼쳐 점수와 도움 상태를 함께 본다.
빠른 UI 시연은 화면 도움 받기 → 설명 더 보기 → 순서대로 보기를 사용한다.
이 수동 조작은 감지 점수 자체를 올리지 않는다.

## 검증 결과

- 도움 대상·단계 상태 테스트 10개, 기존 감지 테스트 10개, API 통신 테스트 2개 통과
- 제품 빌드와 변경 코드 ESLint 검사 통과
- Chromium에서 실제 반복 오류를 발생시켜 자동 1→2→3단계 표시 및 SQLite help 로그 조회 확인
- 수동 확장, 닫기/ESC, 재표시 억제, 단계별 필수 항목 안내, 입력 중 안내 해제 후 값 유지 확인
- 1440px 데스크톱과 390px 모바일에서 레이아웃·강조·원래 항목으로 이동 확인
- 완료/다른 화면 이동/키오스크 이동 후 안내와 강조 제거 확인

전송 데이터와 DB는 별도 테스트용 SQLite로 검증했다. 기존 서비스 DB/키오스크 데이터는 변경하지 않는다.
